What it is

One daemon. Your project, in the group.

SintBot runs on your machine and joins the groups your team already uses; each group is bound to one project, so the agent works inside that directory and keeps its context.

  1. Group-project AI

    sintbot is the daemon: one project per group, each turn handed to Claude Code or Codex headless, progress in the group, permissions per group. Free; the full source code is publicly available to view and download. cc-bot is the companion plugin for your own Claude Code session.

    See it on Slack, Feishu and WeCom →
  • 3platforms — Slack, Feishu and WeCom
  • 2agent runners — Claude Code and Codex
  • 6model backends, swappable per group
  • 16built-in design styles

  • 1,900+unit tests

01 · Platforms

Slack, Feishu and WeCom, all supported.

A group can be a Slack channel, a Feishu group or a WeCom group — each one picks, and one daemon serves all three. The core is the same everywhere: one project per group, just talk to it, no public IP, progress you can stop, the same permissions and console.

In a Feishu group

  • Streaming card

    The card updates while the work runs — how long, what it is doing now, a line per finished step; the answer and its buttons land in the same card, the steps folded away.

  • Whiteboard loop

    Draw arrows or leave notes on the board, press “edit per annotation”, and the revised image returns to the same card.

  • Nine group actions

    Send files, images and messages, read history, reply, edit, recall, download group files, react — and a reaction or card button can trigger it.

  • WebSocket long connection

    The daemon dials out; nothing dials in. No public IP, no webhook.

In a Slack channel

  • Progress in the thread

    A receipt first, throttled progress messages in the thread, the final answer as its own message, then a done mark.

  • Native “Working…” status

    Slack’s own agent status, on the free plan too; stop, skip and status buttons in the thread, plus an App Home page.

  • Commands that survive Slack

    When Slack has taken the slash, use a ! prefix or one catch-all command. The console’s Slack card runs a preflight, lists channels and binds a group.

  • Socket Mode, proxy-friendly

    Outbound only, no public IP; on a restricted network it tunnels through an http proxy.

In a WeCom group

The newest of the three and the least used in real teams so far — feedback welcome.

  • Long connection, no verification

    A smart bot in API mode on a long connection: no public IP, no domain, and a free unverified enterprise is enough.

  • Answers when @-mentioned

    WeCom delivers only messages that @ the bot. Small groups can turn on a follow-up window that answers without @; it is off by default.

  • Names, images and files

    Authorize the official wecom-cli and the group shows members’ names and the bot can send images and files; without it, it still works with user IDs.

  • Streaming replies

    Replies stream into the group; one longer than ten minutes carries on in the next message, and Markdown the client cannot show is rewritten.

Shared core

02 · How it works

From one sentence to delivery.

The daemon on your machine checks the group’s permissions, hands the turn to Claude Code or Codex inside the project directory, and streams progress back — on whatever model you chose for that group.

03 · Models

Same agent. Any brain.

Claude Code against any Anthropic-compatible endpoint — GLM, DeepSeek, Kimi, MiniMax, or an open-source model you host yourself — or Codex through the machine’s own ChatGPT login. The daemon treats them all alike: switching only changes what the next turn starts with, and the project’s memory stays.

  • Claudelocal login, no key needed
  • GPTvia your Codex subscription
  • GLMyour own key
  • DeepSeekyour own key — our pick without a subscription
  • MiniMaxyour own key
  • Kimiyour own key — custom endpoint

No Claude subscription or ChatGPT? Use DeepSeek: paste an API key and it runs. Zhipu GLM and MiniMax work the same way; Kimi and others can be added as custom endpoints.

  1. 01

    Switch in the group

    /model lists, /model plus a name switches — anyone in the group can. A switch opens a fresh conversation; the memory files carry over.

    • /model
    • fresh conversation
    • anyone in the group
  2. 02

    Configured per group

    Each group has its own model and runner; provider settings stack, so chat can go to a fast model and heavy turns to a slow one.

    • per group
    • fast / slow split
    • your keys
  3. 03

    Memory outlives the model

    The project’s CLAUDE.md, AGENTS.md and memory directory are handed to whichever agent starts. Text-only models work too: images become placeholder text.

    • CLAUDE.md
    • AGENTS.md
    • text-only safe

04 · Design system

Bring a reference. Get a style the bot actually follows.

Point it at a site, a project folder or an image you like and it distills a style file, or start from one of sixteen built-in styles. The agent reads that file before every image and page, and checks its work against it before handing anything over.

  1. Distill a style from a reference

    Paste a public URL or pick a project folder in the console, mini program sources included. It reads the stylesheets, ranks colors, fonts and radii by how often they appear, and fills in a new style: background, text, accent and muted colors, corner radius and shadow depth. Each guess shows its evidence, which colors and how many times, so you know what to adjust before you save. For a picture, send it to the group: the agent pulls a palette from it, then works out the mood and the do’s and don’ts with you in the conversation.

    • from a URL
    • from a project folder
    • from an image
    • evidence for every guess

  2. A style file the agent must read

    DESIGN.md at the project root holds the tokens, a written description, do’s and don’ts and an image prompt. The agent reads it before any image or page, and the tokens go into every turn’s brief. A project can keep one file per surface, such as a mini program and an admin panel; company rules go in a user-level folder that every group shares.

    • 16 built-in + 9 alternates
    • one file per surface
    • Lucide · Tabler · Phosphor · Pixelarticons

  3. Checked before it is handed over

    Before anything is handed over, the result is checked against the style file: colors, radii, fonts, icon parameters, Chinese fallbacks, and whether each font will actually load on macOS and Windows. The findings go into the hand-off note. A layout audit then renders the page at three widths and measures overlapping or clipped text, small tap targets, low contrast and tiny type.

    • style check
    • layout audit
    • font availability

  4. Images without an API key

    Images go through the Codex subscription already signed in on the machine, whatever model the group runs, so there is no API key to manage. The group stays free while it paints, and a progress card updates itself until the image lands. It can edit an existing image, repaint just a masked area or give a true transparent background, and the project’s style file comes along every time.

    • edit an existing image
    • masked repaint
    • transparent background

  5. Prototypes the group can open

    A finished HTML prototype is served on your local network from a port fixed per group, so people in the group can open it on their phones. It keeps running after the turn ends, stops itself after 30 idle minutes, and shows up in the console with a Stop button.

    • LAN preview
    • fixed port per group
    • stops when idle

The whiteboard loop

Feishu only

The first time it needs to show an image, it creates a whiteboard and pins it as a tab at the top of the group. Draw arrows, add sticky notes or comment on the board, then say “revise per the annotations” in the group; with auto-detection on, a card appears by itself and one click starts the revision. The new version lands next to the original, and every version and mark stays on the board, so the board becomes the design’s history. Only design work goes on it: material to browse is sent as a searchable page, and a choice between options as a numbered contact sheet.

05 · Scenarios

Six groups, six jobs.

The same daemon, bound to different projects: ask in the group, watch it work, take the result.

  1. #bugs

    Paste the error; a PR comes back.

    A 500 trace lands in the engineering group.

    SintBot reads the trace, finds the cause in the project directory, fixes it, opens the PR and posts the diff in the thread.

    Why it wins: error, fix, PR — one thread, nobody at a terminal.

  2. #design

    One sentence, one homepage.

    A designer asks for a first version of the landing page.

    It reads the style file — or first offers three candidates, say tech-dark, precision-mono and swiss-grid — builds the page and posts the check result with it.

    Why it wins: the rules are in the repo, and the bot proves it followed them.

  3. #standup

    A standup that files itself at 09:30.

    Someone types one sentence to schedule it.

    At 09:30 the task fires like an incoming message: SintBot collects 24 hours of commits and posts the summary.

    Why it wins: happens whether or not humans show up.

  4. #ship-room

    Swap the brain mid-project.

    Someone types /model and a name.

    Same project, same memory files — the next turn runs on GLM instead of Claude. Cost is your call, per group.

    Why it wins: one agent, many brains, no reconfiguration.

  5. #deploys

    Read-only here, full access there.

    Two groups are bound to the same project.

    The read-only group can look, not touch; only the full-access group changes code and deploys. Secrets are masked before anything leaves.

    Why it wins: permissions live on the group, not in someone’s head.

  6. #review

    Review the prototype without leaving the group.

    The page is done; the team wants to click through it.

    SintBot serves it on the local network and posts the link; /issue files feedback with the last turn’s technical fingerprint attached.

    Why it wins: feedback lands with context, not screenshots.

06 · Governance

Read-only until you say otherwise.

Three layers, all set per group and never globally — a group you have not configured can read and nothing else.

  1. ①

    Execution mode

    Read-only or full access. Unset means read-only.

  2. ②

    Tool allow / deny list

    Three presets — read-only, developer, full trust — or your own list.

  3. ③

    Directory fence

    File tools stay inside the group's project directory, and groups bind only inside your projects root — symlinks included. Shell commands aren't sandboxed; for OS-level isolation, run it as its own user or in a VM.

  1. 01

    Redacted on the way out

    Thirteen patterns are masked before a message reaches the group — bearer tokens, JWTs, API-key prefixes, AWS, GitHub, PEM, key-value secrets, emails, phones. Secrets always; PII per group.

    • 13 patterns
    • secrets always
    • PII per group
  2. 02

    Eight commands, in the group

    /status reports elapsed time, steps, latest activity, queue and session; /hud shows quota. The group is warned when the Claude 5-hour window passes 90% or the Codex 7-day window passes 95%.

    • /help
    • /model
    • /new
    • /stop
    • /skip
    • /status
    • /issue
    • /hud
  3. 03

    Quiet when it should be

    Pause a group and nothing runs, scheduled tasks included. Small talk gets no reply; a recalled message stops its turn. /issue files feedback with the last turn’s fingerprint attached.

    • pause a group
    • recall stops the turn
    • feedback book

Browser takeover

Feishu only

When a job in its browser hits a login, a verification code, a slider or a QR code, it posts a card: a screenshot of that page, why it needs you, one button. Tap it and work the page yourself from your phone or desk — tap, drag, type, pinch to zoom; the login stays on its side and it carries on. The link opens once, lasts 10 minutes by default and reaches only that page, and the card flips to in use, ended or expired. Nobody pastes a password or a code into the group.

08 · Reliability

Built to run for weeks.

A daemon nobody watches has to look after itself: turns cannot hang, queues cannot pile up, restarts lose nothing.

  1. 01

    Never hangs

    A 30-minute cap per turn, two turns at once across groups, “received” after 25 silent seconds, a hard release at 20; sessions compact at 400k tokens and a watchdog reconnects.

    • 30-min cap
    • watchdog
    • auto-compaction
  2. 02

    One queue per group, merged

    One lock and one queue per group; messages that arrive mid-turn are merged into the next turn. /stop clears the queue, /skip only the current turn.

    • one lock per group
    • merge on dequeue
  3. 03

    Restarts redo, not forget

    A turn cut short by a release or restart is redone automatically within two hours. Runs as a service: launchd on macOS, systemd on Linux (experimental); on Windows it prints the NSSM or pm2 command.

    • redo within 2h
    • launchd
    • NSSM
  4. 04

    Scheduled in one sentence

    Cron, aliases like daily, or plain “every day at 09:00”. A task can wake the agent like a message, post a fixed reminder, or run once.

    • cron
    • natural language
    • one-off
  5. 05

    Says what is going on

    After an upgrade it posts the new abilities to each group. If the model is overloaded it says so plainly, keeps what it had written and carries on when you say “continue”; a compacted session is announced, with the quota left when the model reports one.

    • upgrade broadcast
    • plain-language errors
    • compaction notice
  6. 06

    Small footprint, smart egress

    Node 22+ with two runtime dependencies; Claude Code is a separate install the setup wizard does for you, and Codex is optional. Official Claude goes through your proxy, domestic endpoints connect direct.

    • Node ≥ 22
    • 2 runtime deps
    • auto proxy split

09 · Setup

Free — up and running in minutes.

sintbot is free, installs from npm, and its full source code is publicly available to view and download. The machine that runs it needs Node 22 or later and claude (Claude Code) — the setup wizard installs it if it is missing; log in only if you use Claude itself. Add codex if you want GPT groups.

npm · sintbot v1.0.15 PolyForm Shield Slack · Feishu · WeCom github.com/sintlab/sintbot

From npm to your group in four steps.

The terminal only installs SintBot and sets up a model. The chat platform, group binding, proxy and the rest are set in the local console afterwards.

Or let one line do steps 1–3 on macOS or Linux: it installs Node 22 if needed, sintbot and Claude Code, sets up a model, asks once before installing the background service, then opens the console:

curl -fsSL https://sintbot.com/install.sh | bash

  1. 01

    Install from npm

    npm i -g sintbot

    Installs the sintbot command. The wizard in step 2 installs Claude Code if it is missing; to use Claude itself, log in once with claude auth login. DeepSeek, GLM and other key-based models need no login.

  2. 02

    Set up a model

    sintbot setup

    It checks the machine and whether you’re logged in to Claude or Codex; if neither, it recommends DeepSeek and runs a trial turn as soon as you paste the API key. That is all it asks.

  3. 03

    Keep it running

    sintbot service install

    Restarted on crash and started at login (macOS launchd; Linux systemd is experimental; on Windows it prints the commands to set one up). The local console stays at http://127.0.0.1:4600, even before a chat platform is connected.

  4. 04

    Connect your chat platform

    In the console under Settings: a Slack app created from the manifest in the repository, a Feishu self-built app (China edition, open.feishu.cn) using the long-connection event mode, or a WeCom smart bot in API mode with a long connection — no public IP in any case. Step-by-step: Slack · Feishu · WeCom. Bind the group to a project folder under Groups, then @ the bot in it.

FAQ

Asked often, answered plainly.

What is SintBot?
A self-hosted daemon that binds a chat group — Slack, Feishu or WeCom — to a project on your own machine. Anyone in the group can hand it work; it runs Claude Code or Codex inside that project and posts progress and results back to the group.
How is it different from cc-bot?
Both are free; cc-bot is MIT-licensed, while SintBot's full source code is publicly available to view and download under PolyForm Shield 1.0.0. cc-bot is a Claude Code plugin: it lives inside your interactive session and uses that session's model. SintBot is a standalone daemon — nobody needs to keep a terminal open, each group has its own project, model and permissions, it drives both Claude Code and Codex, and it comes with a local console.
Which models can it use?
Claude through your local Claude Code login, GPT through your Codex subscription login, and DeepSeek, GLM or MiniMax with your own keys (without a subscription we recommend DeepSeek). Kimi or any other endpoint that speaks the Anthropic API — including an open-source model you host yourself — can be added as a custom endpoint. Each group picks its own, and anyone in the group can switch with /model.
Does switching models lose the project's memory?
No. A switch starts a fresh conversation, but the project's CLAUDE.md, AGENTS.md and memory directory are handed to whichever agent runs next, so conventions and long-term notes carry over. Long sessions are compacted automatically.
Where do my code and data live?
On your machine: project directories, sessions, memory and logs stay there. The daemon talks only to the services you configure — your chat platform and your model endpoints — and nothing is sent to us. Secrets are masked before any message reaches the group.
Do I need a server or a public IP?
No. It runs on a computer you keep on — a Mac is the tested setup; Linux support is experimental and Windows is not yet verified — and it only dials out: Socket Mode for Slack, a WebSocket long connection for Feishu, a long connection for WeCom. The console stays on that machine unless you choose to open it up.
What can the agent do by default?
Read only. Permissions are set per group, never globally: an unconfigured group can read and nothing else. You can grant a tool preset or full access. File tools always stay inside the project directory bound to that group, but with full access shell commands can reach anything your user account can.
How do I get SintBot?
Install it from npm: npm i -g sintbot, then sintbot setup. It is free, and its full source code is publicly available to view and download under PolyForm Shield 1.0.0: use and modify it for yourself, your team or your company, but not to build a competing product. Source and docs are at github.com/sintlab/sintbot.
Do I need a Claude subscription?
No. The setup wizard checks whether this machine is logged in to Claude or to Codex (ChatGPT); if neither, it recommends DeepSeek — paste an API key and it runs a trial turn on the spot. Claude Code is still the agent framework; it just needs no login. Without Claude or ChatGPT you lose only GPT groups and image generation.
Can I use it in mainland China?
Yes. Use Feishu as the chat platform and DeepSeek (or the mainland sites of Zhipu GLM, MiniMax or Kimi) as the model: they connect directly, with no proxy. A proxy is needed only for Claude, ChatGPT or Slack.
Does it work with Lark?
Not yet. SintBot connects to Feishu, the China edition (open.feishu.cn). Lark workspaces (larksuite.com) run on a separate open platform and are not supported yet.
