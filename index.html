SintBot 1.3.0 · first release scope

A coding agent in one Feishu group.

On your Mac, SintBot connects one Feishu group to one project. A message starts a Codex turn through the built-in core; the final answer returns to the group.

macOS · one Feishu group · Codex message path

What 1.3.0 covers

Start with a working core path.

Runs on macOS

The first version is validated on Mac. Linux and Windows support will follow.

One Feishu group

One group is bound to one local project. The first release does not support multiple groups in one service.

Codex message turn

Send a task in the group; Codex works in the bound project and returns its answer. Start read-only, and keep the foreground terminal open.

Later updates

More paths are coming.

Feishu whiteboards, multiple groups, Slack, WeCom, the management console, schedules and terminal chat are outside the first built-in-core support scope. Existing installations using these features should stay on their current version until a compatible upgrade path is published.

Install 1.3.0 on your Mac.

Requires Node.js 22+ and a working, authenticated local Codex. The installer preserves existing global installations and services. Do not migrate a multi-group installation with this single-group release.

curl -fsSL https://sintbot.com/install.sh -o /tmp/sintbot-install.sh
bash /tmp/sintbot-install.sh --dry-run
bash /tmp/sintbot-install.sh

Frequently asked

A clear first step.

What is SintBot?

A self-hosted coding assistant for a project group. The first 1.3.0 core path runs a Codex message turn in one Feishu group on macOS.

Can I upgrade my multi-group installation?

Not to this restricted path. Keep your current service until a compatible multi-group upgrade and recovery procedure is published.

Are whiteboards and other chat platforms included?

No. Whiteboards, Slack and WeCom are planned for later releases of the built-in-core path.

Where can I find installation instructions?

Use the version 1.3.0 installation guide on this page. The installer adds a separate package directory; then configure one group, initialize fresh state and start in the foreground.
