01

Prepare your project Mac

This guide is for SintBot 1.4.5: macOS, Node.js 22 or later, Codex or Claude Code, and 1–32 Feishu China project groups, running in the foreground.

  • Your project is already on this Mac and you know its absolute path.
  • Node.js is version 22 or later.
  • Codex or Claude Code (at least one) is installed, signed in and working in your local terminal.
  • You can create a Feishu enterprise custom app and add its bot to a test group.
How do I check my environment?
Terminal
node --version
codex --version
claude --version

Node.js and the runner you use should report a version before you continue. Keep using your existing Codex or Claude Code installation and account.

What if a version check fails?

If a command cannot be found, finish installing that tool and open a new terminal. Get Node.js from its official website; follow the official Codex instructions to install it and sign in. The SintBot installer installs SintBot itself.

02

Install SintBot in one command

Copy this into your local terminal. The installer checks the environment, installs the package and verifies the result.

Terminal
curl -fsSL https://sintbot.com/install.sh | bash
Installation complete

When you see Installed and verified SintBot 1.4.5, installation is complete. Continue with Feishu and project configuration.

Optional: preview the installation plan

To inspect the plan before installing, use this command instead. It downloads no package and changes no configuration. Then run the installation command above.

Terminal
curl -fsSL https://sintbot.com/install.sh | bash -s -- --dry-run
Optional: check the version and help
Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" --version
"$SINTBOT" help

SintBot is installed in ~/.local/share/sintbot. Continue below to connect Feishu and your project.

03

Set up Feishu and your group

Create an enterprise custom application in the Feishu developer platform, then complete these steps in order.

  1. Enable the bot.Add the bot capability to the application.
  2. Grant message permissions.Allow message reception and replies sent as the bot.
  3. Choose a long connection.Select long-connection event delivery and subscribe to message reception.
  4. Publish and join the group.Publish the app, add its bot to a dedicated test group and obtain that group’s oc_… chat ID.
Keep credentials on your Mac

In the terminal that will start SintBot, set the application ID and secret as the FEISHU_APP_ID and FEISHU_APP_SECRET environment variables. Never send the app secret to a chat or commit it to your project.

Both variables must be present in every new terminal session. The configuration below stores their names, not your secret.

Enter your app credentials

Open your application in the Feishu developer platform and find App ID and App Secret on its Credentials & Basic Info page. In the default macOS zsh shell, run these lines in order, entering each value at its prompt. Secret input is hidden and is not saved as a command in shell history.

zsh
read -r "FEISHU_APP_ID?Feishu App ID: "
read -rs "FEISHU_APP_SECRET?Feishu App Secret: "
printf '\n'
export FEISHU_APP_ID FEISHU_APP_SECRET
[[ -n "$FEISHU_APP_ID" && -n "$FEISHU_APP_SECRET" ]] && printf 'Credentials set\n'

Credentials set confirms both values are set without showing the secret. Continue the remaining steps in this terminal. Set the credentials again when opening a new terminal.

04

Link the group to your project

Create a private configuration directory:

Terminal
mkdir -p ~/.sbot && chmod 700 ~/.sbot

In a text editor, create ~/.sbot/config.json with the following content. Replace the chat IDs and project paths with your own values; with one group, delete the other entry. The project directory must already exist.

config.json
{
  "defaultProvider": "codex",
  "providers": {
    "codex": { "runner": "codex" },
    "claude": { "runner": "claude" }
  },
  "feishu": {
    "appId": "env:FEISHU_APP_ID",
    "appSecret": "env:FEISHU_APP_SECRET",
    "onlyWhenMentioned": false
  },
  "groups": {
    "oc_REPLACE_WITH_FIRST_CHAT_ID": {
      "platform": "feishu",
      "provider": "codex",
      "workdir": "/absolute/path/to/first/project",
      "permissionMode": "dontAsk",
      "codexSteer": true
    },
    "oc_REPLACE_WITH_SECOND_CHAT_ID": {
      "platform": "feishu",
      "provider": "claude",
      "workdir": "/absolute/path/to/second/project",
      "permissionMode": "dontAsk"
    }
  }
}

After saving, restrict access to the configuration file:

Terminal
chmod 600 ~/.sbot/config.json
How does this configuration work?
workdir
The project directory bound to the group. Use an absolute path.
permissionMode: "dontAsk"
This example starts restricted, so you can verify messages and project access first. Use "bypassPermissions" (full access) once it should edit files and run commands.
onlyWhenMentioned: false
Ordinary messages in this group are received. Start with a dedicated test group.
provider
codex or claude, chosen per group. With one group, delete the other entry. Add "model" to providers.claude to pin a Claude model.
codexSteer: true
Messages sent while a Codex task runs join that task; Claude Code groups queue them.
How do I require a bot mention?

Set onlyWhenMentioned to true and add the app’s actual botOpenId to the feishu object. This is the bot’s Open ID, not the app or chat ID. Startup checks reject this setting if the bot ID is missing.

05

Start a new installation

Copy this block into the same terminal where you entered the Feishu credentials. Run it once for a new installation only. For later restarts, use the command in the next section.

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" init --config "$HOME/.sbot/config.json" &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --preflight &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui

This initializes the message journals, checks the configuration and runners, connects to Feishu and opens the local console. If a step fails, the remaining steps do not run. Keep the terminal open, then verify a message in the group.

Initialize only once

If the journal already exists, check whether initialization has finished. Use the start command for normal restarts; do not delete task logs. Connect only one SintBot process to a Feishu application at a time.

06

Verify with a real message

Send this in the Feishu group you just connected:

Read the first line of this project’s README.md and reply with only that line.

Compare the reply with the file. This checks the group connection, the runner and the project path together.

Commands and console

Any text message is a task; the reply card appears once the model starts, or after 25 seconds if it is still working without output. While it runs, the card shows how long it has run, what it is doing and the steps already delivered, which fold into a Process section at the end. These commands are answered at once and never take a task slot:

/status
Model, project, busy or idle (steps and current work while busy), and queue.
/skip
Cancel only the current task; queued messages run next and the conversation is kept.
/stop
Stop the current task and cancel queued ones; the conversation is kept.
/new
Start a new conversation, forgetting the previous one, while the group is idle.
/model
List models; /model name switches while the group is idle and starts a new conversation.
/hud
Quota of the current model and usage of this conversation.
/issue text
Log feedback for the console.
/help
List commands, with this group's project and model.

Send a command as a message of its own; except for /issue and /model, add no other text. If the Feishu app subscribes to the message-recall event, recalling your own message cancels it.

With --ui, open http://127.0.0.1:4600 on this Mac to see every group, stop tasks, start a new conversation for an idle group, bind new groups, switch the model or project of an idle group, and add or configure models. Set a console password in its settings before enabling LAN access. To add a group without the console, add it to the configuration and restart; it is registered automatically.

Stop and restart

In the running terminal, press Ctrl + C and wait for the process to exit. Confirm the Feishu environment variables are set, then use the same start command:

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui

Use start for normal restarts. Do not run init again.

The bot does not reply

Check the terminal error first. Verify that the application is published, the bot has joined the target group, message permissions and event subscriptions are configured, environment variables are present, and the chat ID and project path are correct. A successful preflight does not prove Feishu authentication or message delivery.

A group is paused or startup reports unresolved receipts

When a group's last result cannot be confirmed, only that group is paused and the other groups keep working. Restart first; if it is still paused, check what the task actually did, then stop the service, run sintbot incident seal --group <group ID> and start again. Do not clear logs, overwrite unknown outcomes or repeatedly resend the same task.
