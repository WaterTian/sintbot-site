APP

Install the macOS app

For an Apple silicon Mac running macOS 12 or later. Install and sign in to Codex or Claude Code first; the App includes Node.js. A Feishu China team identity is needed only when connecting Feishu; local conversations can be used without it.

Download for Apple silicon

  1. Open the disk image and drag SintBot into Applications.
  2. Open SintBot, choose a project and executor, then scan the QR code with Feishu; or choose “Use on this Mac first” to skip the chat app and give tasks on the console’s Chat page, connecting Feishu later.
  3. Once the group is connected, send “Read the first line of README.md and reply with that line only” and compare the reply with your file.

Keep it running

Closing the window leaves the App in the menu bar. Quitting the App keeps the bot running. Choose “Stop SintBot and Quit” to stop both. A service installed by the App stays stopped across logins until you choose Start or reopen the App. “Remove Background Service” preserves configuration and history.

Updates

When a new service version is available, open Settings in the console and choose “Upgrade now”. Update the App itself by replacing it with a newer disk image. An existing SintBot service on this Mac is reused.

Background activity in System Settings

The service can appear under Node.js Foundation and may be grouped with other Node.js services.

For terminal installation, follow the steps below.

You can also choose “Start on this Mac” without Feishu. Later, stop the service and use sintbot connect --attach to add Feishu while keeping local history.

01

Prepare your project Mac

The terminal steps below are for SintBot 1.4.21 on macOS with Node.js 22 or later and Codex or Claude Code. Start with local conversations, or connect 1–32 Feishu China project groups. The desktop App includes Node.js.

  • You can start with the automatically created project folder or choose an existing project on this Mac.
  • Node.js is version 22 or later.
  • Codex or Claude Code (at least one) is installed, signed in and working in your local terminal.
  • You can confirm the connection using Feishu on your phone with a team identity.
How do I check my environment?
Terminal
node --version
codex --version
claude --version

Node.js and the runner you use should report a version before you continue. Keep using your existing Codex or Claude Code installation and account.

What if a version check fails?

If a command cannot be found, finish installing that tool and open a new terminal. Get Node.js from its official website; follow the official instructions for your chosen coding agent to install it and sign in. The SintBot installer installs SintBot itself.

02

Install SintBot in one command

Copy this into your local terminal. The installer checks the environment, installs the package and verifies the result.

Terminal
curl -fsSL https://sintbot.com/install.sh | bash
Installation complete

When you see Installed and verified SintBot 1.4.21, installation is complete. Continue with Feishu and project configuration.

Optional: preview the installation plan

To inspect the plan before installing, use this command instead. It downloads no package and changes no configuration. Then run the installation command above.

Terminal
curl -fsSL https://sintbot.com/install.sh | bash -s -- --dry-run
Optional: check the version and help
Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" --version
"$SINTBOT" help

SintBot is installed in ~/.local/share/sintbot. Continue below to connect Feishu and your project.

03

Connect Feishu in the browser

Run the start command; the browser opens the local setup page. Enter a project name, scan with Feishu on your phone and confirm. Select an enterprise or team identity; create a team in Feishu first if you do not have one.

Terminal
"$HOME/.local/share/sintbot/bin/sintbot" start --ui
  1. Name the project and click Start.A new folder is created under ~/Projects by default, or enter the absolute path of an existing one; pick the runner if both are installed.
  2. Scan and confirm.The QR code is on the page. Confirm the team that will own the bot app.
  3. The app and group are created for you.The page shows each step: credentials, checks, group, configuration. A few seconds later it switches to the console; send a task in the new group. No configuration to write, no app secret to copy.

Not ready to connect Feishu? Below the form, choose “Use on this Mac first”: no scan, no app; the console opens on its Chat page and you give tasks on this Mac. To add Feishu later, stop the service, run sintbot connect --attach and start again; existing configuration, records and conversations are kept.

Before scanning, SintBot reads the selected executor’s live model list and saves its recommended model and thinking depth for the new group. The setup page shows the selected values; you can change them later in Groups · Projects. If the live recommendation is unavailable, setup stops before creating a new app: check the executor’s login and network, then retry. Existing group choices are preserved.

Administrator approval required, or setup did not finish?

Permissions and publishing approval depend on your organization. If the group could not be created, the page asks you to create one by hand, add the bot and paste the group ID to continue; other failures offer Retry or Back. Tick the basic option if you are not an organization administrator. See the full install guide for the terminal route (sintbot connect) and manual setup.

Where is configuration saved?

App credentials are saved on this Mac in ~/.sbot/config.json with file permissions 0600. Never post the file or secret in a group or commit it. Setup never replaces a configuration that already has bound groups, and the setup page is reachable only from this Mac.

04

Choose the project on the setup page

By default setup creates ~/Projects/sintbot with a README and binds it to the new group. To connect an existing project, enter its absolute path in the existing-project field; the directory must exist. Do not use your entire home directory as a project. Afterwards, manage project folders and models under Groups · Projects in the console.

Prefer the terminal?

The same flow runs as sintbot connect; --name, --workdir, --provider and --basic map to the options on the page. See the full install guide.

05

Everyday start

When setup completes the service is already running; there is nothing else to run. Every later start uses the same command:

Terminal
"$HOME/.local/share/sintbot/bin/sintbot" start --ui

Keep the terminal open. Settings → Feishu shows the connection status; Groups · Projects manages bindings. Public console access and administrator sign-in are optional.

The console shows “Needs attention”?

After a power loss or forced restart during a task, the service holds the groups whose result is unknown and lists them on the overview’s “Needs attention” card; the service still starts when every group is held, so the console stays available. When the background service supports automatic restart and the other groups are idle and settled, click “Seal and continue”: the record is archived unchanged, that message is not processed again, and the service restarts by itself with a new record; resend the message if needed. In a foreground run, seal from a terminal as described in the full install guide.

Restart an existing installation directly

Do not scan or initialize again for a normal restart. If you used --config or --data-dir, pass the same flags on every start.

06

Verify with a real message

Send this in the Feishu group you just connected:

Read the first line of this project’s README.md and reply with only that line.

Compare the reply with the file. This checks the group connection, the runner and the project path together.

Commands and console

Any text message is a task; the reply card appears once the model starts, or after 25 seconds if it is still working without output. While it runs, the card shows how long it has run, what it is doing and the steps already delivered, which fold into a Process section at the end. These commands are answered at once and never take a task slot:

/status
Model, project, busy or idle (steps and current work while busy), and queue.
/skip
Cancel only the current task; queued messages run next and the conversation is kept.
/stop
Stop the current task and cancel queued ones; the conversation is kept.
/new
Start a new conversation, forgetting the previous one, while the group is idle.
/model
Opens a tap-to-pick card: choose the backend, model and thinking depth, then confirm. You can also send /model high, /model <model> or /model <backend>. A model or depth change continues the conversation; a backend change starts a new one. Only while the group is idle.
/hud
Quota of the current model and usage of this conversation.
/issue text
Log feedback for the console.
/help
List commands, with this group's project and model.

Send a command as a message of its own; except for /issue and /model, add no other text. If the Feishu app subscribes to the message-recall event, recalling your own message cancels it.

With --ui, open http://127.0.0.1:4600 on this Mac to see every group, stop tasks, start a new conversation for an idle group, bind new groups, switch the model or project of an idle group, and add or configure models. Set a console password in its settings before enabling LAN access. To add a group without the console, add it to the configuration and restart; it is registered automatically.

Model and thinking depth are chosen per group: on the group card, the Model row picks the backend and model and the next row picks the depth, from lists read live from the local Codex and Claude Code. Choose the model and thinking depth for Codex, Claude and DeepSeek on each group card. DeepSeek connection settings and API key stay in the model library; other third-party endpoints keep their connection model there. After the upgrade, each model card’s existing model and depth move into its groups with the same effective values and no session reset.

Model settings are grouped into model and reasoning, context and compaction, and connection. For Codex, choose the executor default or a custom context window; known limits are checked on save. Compaction also offers default or custom, with numeric inputs shown only when needed. Codex uses a threshold and Claude Code a compaction window; either may compact earlier. Existing explicit global values become independent settings on existing models. Changes apply to the next turn and preserve the session. Capacity details distinguish requested settings from runtime reports.

For Claude Code groups, SintBot can compact the current session between turns when the CLI reports compaction support and the context reaches half of a custom compaction window. It uses a spare concurrency slot and stays silent in the group. A new message interrupts compaction before starting its turn; a window of 0 disables only idle compaction; compaction during a turn follows the executor’s defaults. /hud shows the compaction line and last completion time. Claude subscription quota prefers rate-limit events reported by the executor.

Stop and restart

In the running terminal, press Ctrl + C and wait for the process to exit. Keep the configuration from setup and use the same start command:

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" start --ui

Use start for normal restarts. Do not run init again.

The bot does not reply

Check the terminal error first. Verify that the application is published, the bot has joined the target group, message permissions and event subscriptions are configured, the credentials are valid and the project group is bound. A successful preflight does not prove Feishu authentication or message delivery.

A group is paused or startup reports unresolved receipts

When a group's last result cannot be confirmed, only that group is held and the console stays available. Check what the task actually did. If the console offers “Seal and continue”, use it to archive the record unchanged and restart the service. Otherwise stop the service, run sintbot incident seal --group <group ID> and start again. Do not clear logs, overwrite unknown outcomes or blindly resend the task.
