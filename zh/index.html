它是什么

一个守护进程，把项目放进群里。

SintBot 跑在你自己的机器上，进的是团队本来就在用的群；一群绑一个项目，agent 在项目目录里干活、记得上下文。

  1. 群项目 AI

    sintbot 是守护进程：一群一项目，每一轮交给无头的 Claude Code 或 Codex，进度在群里、权限按群管。MIT 开源；cc-bot 是配套插件，装进你自己的 Claude Code 会话。

    看飞书、Slack 与企业微信里的样子 →
  • 3个平台 —— 飞书、Slack 与企业微信
  • 2套 agent runner —— Claude Code 与 Codex
  • 6种模型后端，按群可换
  • 16套内置设计风格
  • 13类出站脱敏模式
  • 1,900+个单元测试

01 · 平台

飞书、Slack 与企业微信，都支持。

群可以是飞书群、Slack 频道，也可以是企业微信群——每个群自己选，一个守护进程同时接三边。核心处处一样：一群一项目、群里直接说、免公网 IP、进度可见可停、同一套权限与控制台。

在飞书群里

  • 流式卡片

    卡片边跑边更新：已跑多久、正在做什么、每完成一步多一行；做完正文和按钮落在同一张卡里，过程收进折叠区。

  • 画板闭环

    在画板上画箭头、写便签，点「按标注改图」，改好的图回到同一张卡。

  • 群内九个动作

    发文件、发图、发消息、读历史、回复、编辑、撤回、下载群文件、表情回应——点个表情、点卡片按钮也能触发它。

  • WebSocket 长连接

    只有守护进程往外连，没有东西往里连。不要公网 IP，不要 webhook。

在 Slack 频道里

  • 线程内进度

    先回一条回执，线程里节流刷新进度，最终答案单独落地，最后打勾。

  • 原生 Working… 状态

    Slack 自己的 agent 状态条，免费版也有；线程里有停止 / 跳过 / 状态按钮，另有 App Home 主页。

  • 命令不被 Slack 吃掉

    斜杠被 Slack 占用时，用 ! 前缀或一条总入口命令。控制台的 Slack 卡负责预检、列频道、绑群。

  • Socket Mode，可走代理

    只出不进，免公网 IP；受限网络可走 http 代理隧道。

在企业微信群里

三个平台里最新接入的，真实环境里用得最少，欢迎反馈。

  • 长连接，企业不用认证

    智能机器人 · API 模式 · 长连接：不要公网、不要域名，免费注册、未认证的企业就能用。

  • @ 它就回

    企业微信只推送 @ 机器人的消息。小群可以打开「不 @ 也回复」的跟进窗口，默认关闭。

  • 姓名、发图、发文件

    装好并授权官方命令行工具 wecom-cli，群里就显示成员姓名、机器人能发图发文件；不装也能用，只是显示账号。

  • 流式回复

    回复在群里流式输出；超过 10 分钟的回复自动接成下一条，客户端显示不了的 Markdown 会自动改写。

共同内核

  • 一群一项目
  • 群里直接说
  • 免公网 IP
  • 进度可见可停
  • 同一套权限与脱敏
  • 同一个控制台

02 · 怎么跑

从一句话到交付。

你机器上的守护进程核对这个群的权限，把这一轮交给项目目录里的 Claude Code 或 Codex，进度回流到群——模型是你给这个群选的那一个。

03 · 模型

同一套 agent，任意大脑。

Claude Code 接任何 Anthropic 兼容端点——GLM、DeepSeek、Kimi、MiniMax，或你自己部署的开源模型；Codex 则用机器上的 ChatGPT 登录态。守护进程一视同仁：换模型只是换下一轮启动时带的参数，项目记忆不变。

  • Claude本机登录态，不用配 key
  • GPT走你的 Codex 订阅
  • GLM你自己的 key
  • DeepSeek你自己的 key，没订阅时推荐
  • MiniMax你自己的 key
  • Kimi你自己的 key，自定义端点

没有 Claude 订阅也没有 ChatGPT？推荐 DeepSeek，填一个 API key 就能跑；智谱 GLM、MiniMax 同样可以，Kimi 等可以在控制台自定义添加。

  1. 01

    群里就能切

    /model 列出可用，/model 加名字就切，群里谁都能切。切换会开新对话，项目记忆文件带过去。

    • /model
    • 新对话
    • 全员可切
  2. 02

    按群配置

    每个群有自己的模型和 runner；provider 级设置可以叠加，闲聊走快模型、重活走慢模型。

    • 按群
    • 快慢分流
    • 你的 key
  3. 03

    记忆比模型活得久

    项目的 CLAUDE.md、AGENTS.md 和记忆目录，哪个 agent 启动都会拿到。纯文本模型也能用：图片换成占位文本。

    • CLAUDE.md
    • AGENTS.md
    • 纯文本模型可用

04 · 设计系统

机器人真的遵守的设计系统。

16 套内置风格、一份放在项目里的风格档、一道交付前的核对。

  1. agent 必读的风格档

    项目根目录的 DESIGN.md：tokens、文字说明、Do/Don't、生图模板，出图出页面前必读。一个项目可有多份；公司规范放进用户级目录，所有群共用。

    • 内置 16 套 + 备选 9 套
    • 从参考图或网址提色
    • lucide · tabler · phosphor · pixelart

  2. 交付前先核对

    对照风格档查颜色、圆角、字体、图标参数、中文兜底，以及字体在 mac 与 Windows 上是否真的显示——结果贴进交付说明。再按三档宽度真渲染，量重叠、裁切、点击目标、对比度、字号。

    • 风格核对
    • 渲染几何体检
    • 字体可得性

  3. 生图不用 key

    生图借机器上的 Codex 订阅：零 API key，不占群锁，画的时候群里有一条自己更新的进度。原图上改、遮罩局部重绘、透明底，项目风格档自动带上。

    • 原图上改
    • 局部重绘
    • 透明底

  4. 原型直接在群里看

    做好的原型起成局域网服务，端口按群固定；跨轮存活，闲置 30 分钟自动停，控制台里可见可停。

    • 局域网预览
    • 按群固定端口
    • 闲置自动停

画板闭环

飞书 限定

第一次要展示图时，守护进程自动建画板并挂成群标签页。画箭头、贴便签、写评论，点「按标注改图」，结果回填同一张卡。历史版本与标注全部保留，画板就是这份设计的演变档案。画板只放设计方案：要翻找的做成可搜索的网页发群，要挑一个的出带序号的对照图。

05 · 场景

六个群，六种活。

同一个守护进程，绑不同的项目：群里说一句，看着它干，拿走结果。

  1. #bugs

    报错贴进群，回来的是 PR。

    研发群里贴了一段 500 堆栈。

    SintBot 读堆栈、在项目目录里定位原因、改掉、开 PR，把 diff 贴回线程。

    为什么赢：报错、修复、PR 在同一条线程里，终端前不用有人。

  2. #design

    一句话，要一版首页。

    设计群里有人要落地页的第一版。

    它读项目风格档——没有就先给三个候选，比如科技深色、精密仪表、瑞士网格——出图做页面，核对结果随交付一起贴出来。

    为什么赢：规范在仓库里，机器人还要证明自己照办了。

  3. #standup

    每天 09:30，日报自己来。

    有人在群里一句话排了个定时任务。

    到 09:30，任务像收到一条消息那样触发：SintBot 汇总 24 小时的提交，发到群里。

    为什么赢：人到不到，日报都在。

  4. #ship-room

    项目做到一半，换个大脑。

    有人在群里敲了 /model 加一个名字。

    同一个项目、同一批记忆文件，下一轮从 Claude 换成 GLM 接着干。成本自己定，按群定。

    为什么赢：一套 agent，多个大脑，不用重新配。

  5. #deploys

    这个群只能看，那个群才能改。

    两个群绑了同一个项目。

    只读群能看不能动；完全访问群才能改代码、部署。敏感值出群前先打码。

    为什么赢：权限挂在群上，不靠人记。

  6. #review

    原型不出群就能评。

    页面做完了，团队想点开看看。

    SintBot 起成局域网预览，链接发群；/issue 一句话提反馈，上一轮的技术指纹自动附上。

    为什么赢：反馈带着上下文来，不是一张截图。

06 · 治理

默认只读，你说了才能动。

三层权限，全部按群设、没有全局开关——没配置过的群，只能读。

  1. ①

    执行模式

    只读，或完全访问。没设就是只读。

  2. ②

    工具白名单 / 黑名单

    三档预设：只读、开发、全信任；也可以自己列。

  3. ③

    目录围栏

    文件工具只在本群绑定的项目目录里动，能绑的目录只限项目根目录之内，符号链接绕不出去。命令行没有沙箱；要系统级隔离，请用单独的系统用户或虚拟机跑。

  1. 01

    出站先脱敏

    消息到群之前先过 13 类模式：Bearer、JWT、API key 前缀、AWS、GitHub、PEM、键值对、邮箱、手机号。密钥永远遮，PII 按群开关。

    • 13 类模式
    • 密钥永远遮
    • PII 按群
  2. 02

    群里八条命令

    /status 报已跑时长、步数、最近动静、排队、会话；/hud 报额度。Claude 5 小时窗用过 90%、Codex 7 天窗用过 95%，群里会提醒。

    • /help
    • /model
    • /new
    • /stop
    • /skip
    • /status
    • /issue
    • /hud
  3. 03

    该安静时安静

    群一暂停就什么都不跑，定时任务也停。闲聊不回；消息撤回，那一轮就停。/issue 提反馈，自动附上一轮的技术指纹。

    • 群可暂停
    • 撤回即停
    • 反馈本

接管浏览器

飞书 限定

它用浏览器干活时撞上登录、验证码、滑块或扫码，会往群里发一张卡：卡住那一页的截图、为什么要你、一个按钮。点开就在手机或电脑上亲手操作那一页——点、拖、输入、两指缩放；登录态留在它那边，它接着干。链接只能打开一次、默认 10 分钟内有效、只通向那一页，卡片会翻成「接管中」「已结束」「已过期」。密码和验证码不用再往群里发。

08 · 长跑可靠

为连跑几周而写。

没人盯着的守护进程得自己照顾自己：轮次不挂死，队列不堆积，重启不丢活。

  1. 01

    永不挂死

    每轮 30 分钟上限，全局同时两轮；25 秒没输出先回「已收到」，卡住 20 秒硬释放；40 万 token 自动压缩，看门狗自动重连。

    • 30 分钟上限
    • 看门狗
    • 自动压缩
  2. 02

    每群一条队列，出队合并

    每群一把锁、一条队列；跑着时来的消息，出队时合并成一轮。/stop 全停含排队，/skip 只跳当前。

    • 每群一把锁
    • 出队合并
  3. 03

    重启补做，不丢活

    被发版或重启打断的那一轮，两小时内自动重做。常驻：macOS 用 launchd，Linux 用 systemd（实验性），Windows 给出 NSSM 或 pm2 的现成命令。

    • 2 小时内补做
    • launchd
    • NSSM
  4. 04

    一句话排定时任务

    cron、daily 别名，或直接写「每天 09:00」。到点可以像收到消息一样叫醒 agent，也可以只发提醒，或只跑一次。

    • cron
    • 中文简写
    • 一次性
  5. 05

    有事说人话

    升级后把新能力发到各个群。模型那边排不上队时说句人话，已经写出来的保住，过一会儿发一句「继续」就接着做；长会话自动压缩会告诉群，查得到额度就一并报上。

    • 升级播报
    • 出错说人话
    • 压缩提示
  6. 06

    依赖少，出网会分流

    Node 22 起，运行时依赖两个；Claude Code 和 Codex 另装，配置向导可以代你装。官方 Claude 走代理，国内端点直连，自动分流。

    • Node ≥ 22
    • 2 个运行时依赖
    • 代理自动分流

09 · 接入

开源，几分钟跑起来。

sintbot 采用 MIT 许可，从 npm 安装。跑它的机器需要 Node 22 及以上和 claude（Claude Code）——没装的话配置向导会替你装；只有用 Claude 本身才需要登录。要开 GPT 群再加 codex。

npm · sintbot v1.0.3 MIT 飞书 · Slack · 企业微信 github.com/sintlab/sintbot

从 npm 到群里，四步。

大部分事由 sintbot setup 完成：检查环境，拿凭据向平台核验，把第一个群绑到一个项目目录。

也可以一行命令做完第 1、3、4 步（macOS / Linux）：需要时先装 Node 22，再装 sintbot，向导里再装 Claude Code，每一步先问你：

curl -fsSL https://sintbot.com/install.sh | bash

在中国大陆？聊天平台用飞书；没有 Claude 订阅就用 DeepSeek，直连、不用代理；Codex 可以不装。向导问「这台机器在中国大陆吗」时答「是」。

  1. 01

    从 npm 安装

    npm i -g sintbot

    装好后就有 sintbot 命令。第 3 步的向导会检查 Claude Code，没装会问要不要替你装；要用 Claude 本身，登录一次 claude auth login；DeepSeek、GLM 等用 key 的模型不用登录。

  2. 02

    建好聊天机器人

    飞书建一个企业自建应用、事件订阅选长连接，或在 Slack 用仓库里的 manifest 建应用，或在企业微信建一个 API 模式、长连接的智能机器人——都不需要公网 IP。分步说明：飞书 · Slack · 企业微信。建好后把机器人拉进群。

  3. 03

    跑一遍向导

    sintbot setup

    先看你登录了 Claude 还是 Codex，都没有就推荐 DeepSeek，粘贴 API key 当场试跑一轮；再选平台、粘贴凭据（当场向平台核验）、选项目根目录、绑定第一个群。最后跑一遍体检，标 ✗ 的先处理掉再往下走。

  4. 04

    常驻运行

    sintbot service install

    崩溃自动拉起、登录即启动（macOS 用 launchd；Linux 的 systemd 为实验性；Windows 上只打印设置命令）。然后在群里 @ 机器人就行。本地控制台在 http://127.0.0.1:4600。

常用命令

  • sintbot doctor — 体检与诊断
  • sintbot service status | logs — 服务在不在、在做什么
  • sintbot agent run "…" — 在终端里只读试跑一轮
  • /model /status /stop /new — 群里：换模型、看进度、叫停、开新会话（Slack 里用 ! 前缀）

姊妹项目

cc-bot：插件版

更想让它待在 Claude Code 里？cc-bot 是一个 Claude Code 插件：装进你自己的会话，群里的消息就交给这个会话处理。支持飞书与 Slack，MIT 许可。

  • SintBot独立守护进程：不用有人守着终端，每个群各有项目、模型和权限。
  • cc-bot插件：跑在你已经打开的 Claude Code 会话里，用的就是这个会话的模型。
/plugin marketplace add WaterTian/cc-bot

然后在 Claude Code 里依次运行 /plugin install cc-bot@cc-bot 和 /cc-bot:setup。

常被问到的，直接回答。

SintBot 是什么？
一个跑在你自己机器上的守护进程：把一个聊天群（飞书、Slack 或企业微信）绑定到一个项目。群里谁都能派活，它在这个项目里运行 Claude Code 或 Codex，把进度和结果发回群里。
它和 cc-bot 有什么区别？
两者都免费、都是 MIT 许可。cc-bot 是 Claude Code 插件，运行在你的交互会话里，用的就是该会话的模型。SintBot 是独立的守护进程：不需要有人守着终端，每个群有自己的项目、模型和权限，同时驱动 Claude Code 和 Codex，并自带本地控制台。
支持哪些模型？
Claude 用本机的 Claude Code 登录，GPT 用你的 Codex 订阅登录；DeepSeek、GLM、MiniMax 用你自己的 key（没有订阅时推荐 DeepSeek）；Kimi 等任何兼容 Anthropic 接口的端点，包括你自己部署的开源模型，都可以作为自定义端点添加。每个群各选各的，群里任何人都能用 /model 切换。
换模型会丢掉项目记忆吗？
不会。换模型会开一段新对话，但项目里的 CLAUDE.md、AGENTS.md 和记忆目录会交给接下来运行的 agent，约定和长期记忆都还在。长会话会自动压缩。
代码和数据存在哪？
都在你自己的机器上：项目目录、会话、记忆和日志都留在本地。守护进程只和你配置的服务通信（聊天平台和模型端点），不会发给我们。消息发进群之前，密钥类内容会先被遮掉。
需要服务器或公网 IP 吗？
不需要。它跑在一台常开的电脑上（Mac 是验证过的环境；Linux 为实验性支持，Windows 尚未验证），只向外连接：飞书用 WebSocket 长连接，Slack 用 Socket Mode，企业微信用长连接。控制台默认只在本机，除非你自己选择开放。
默认情况下 agent 能做什么？
只能读。权限按群设置，没有全局开关：没配置过的群只能读取。你可以给某个群一档工具预设或完全访问。文件工具始终只在这个群绑定的项目目录里，但完全访问下，命令行能碰到你这个系统用户能碰到的一切。
怎么获取 SintBot？
从 npm 安装：npm i -g sintbot，再跑 sintbot setup。免费、MIT 开源，源码和文档在 github.com/sintlab/sintbot。
必须有 Claude 订阅吗？
不需要。配置向导会先看这台机器登录了 Claude 还是 Codex（ChatGPT）；都没有就推荐 DeepSeek，粘贴 API key 当场试跑一轮。执行框架仍是 Claude Code，只是不用登录。没有 Claude 和 ChatGPT 时，用不了的只有 GPT 群和生图。
在中国大陆能用吗？
能。聊天平台用飞书，模型用 DeepSeek（或智谱 GLM、MiniMax、Kimi 的中国站），都是直连、不用代理。只有用 Claude、ChatGPT 或 Slack 才需要代理。
支持国际版 Lark 吗？
暂不支持。SintBot 连的是飞书（open.feishu.cn）；Lark（larksuite.com）是另一套开放平台，目前还不支持。
