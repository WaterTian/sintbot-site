它是什么

一个守护进程，把项目放进群里。

SintBot 跑在你自己的机器上，进的是团队本来就在用的群；一群绑一个项目，agent 在项目目录里干活、记得上下文。

  1. 群项目 AI

    sintbot 是守护进程：一群一项目，每一轮交给无头的 Claude Code 或 Codex，进度在群里、权限按群管。cc-bot 是免费插件，装进你自己的 Claude Code 会话。

01 · 平台

飞书与 Slack，都支持。

群可以是飞书群，也可以是 Slack 频道——每个群自己选，一个守护进程同时接两边。其余完全一样：一群一项目、群里直接说、免公网 IP、进度可见可停、同一套权限与控制台。

飞书

在飞书群里

  • 流式卡片

    卡片边跑边更新：已跑多久、正在做什么、每完成一步多一行；做完正文和按钮落在同一张卡里，过程收进折叠区。

  • 画板闭环

    在画板上画箭头、写便签，点「按标注改图」，改好的图回到同一张卡。

  • 群内九个动作

    发文件、发图、发消息、读历史、回复、编辑、撤回、下载群文件、表情回应——点个表情、点卡片按钮也能触发它。

  • WebSocket 长连接

    只有守护进程往外连，没有东西往里连。不要公网 IP，不要 webhook。

Slack

在 Slack 频道里

  • 线程内进度

    先回一条回执，线程里节流刷新进度，最终答案单独落地，最后打勾。

  • 原生 Working… 状态

    Slack 自己的 agent 状态条，免费版也有；线程里有停止 / 跳过 / 状态按钮，另有 App Home 主页。

  • 命令不被 Slack 吃掉

    斜杠被 Slack 占用时，用 ! 前缀或一条总入口命令。控制台的 Slack 卡负责预检、列频道、绑群。

  • Socket Mode，可走代理

    只出不进，免公网 IP；受限网络可走 http 代理隧道。

02 · 怎么跑

从一句话到交付。

你机器上的守护进程核对这个群的权限，把这一轮交给项目目录里的 Claude Code 或 Codex，进度回流到群——模型是你给这个群选的那一个。

03 · 模型

同一套 agent，任意大脑。

Claude Code 接任何 Anthropic 兼容端点——GLM、DeepSeek、Kimi、MiniMax，或你自己部署的开源模型；Codex 则用机器上的 ChatGPT 登录态。守护进程一视同仁：换模型只是换下一轮启动时带的参数，项目记忆不变。

  • Claude本机登录态，不用配 key
  • GPT走你的 Codex 订阅
  • GLM你自己的 key
  • DeepSeek你自己的 key
  • MiniMax你自己的 key
  • Kimi你自己的 key
  1. 01

    群里就能切

    /model 列出可用，/model 加名字就切，群里谁都能切。切换会开新对话，项目记忆文件带过去。

    • /model
    • 新对话
    • 全员可切
  2. 02

    按群配置

    每个群有自己的模型和 runner；provider 级设置可以叠加，闲聊走快模型、重活走慢模型。

    • 按群
    • 快慢分流
    • 你的 key
  3. 03

    记忆比模型活得久

    项目的 CLAUDE.md、AGENTS.md 和记忆目录，哪个 agent 启动都会拿到。纯文本模型也能用：图片换成占位文本。

    • CLAUDE.md
    • AGENTS.md
    • 纯文本模型可用

04 · 设计系统

机器人真的遵守的设计系统。

16 套内置风格、一份放在项目里的风格档、一道交付前的核对。

  1. agent 必读的风格档

    项目根目录的 DESIGN.md：tokens、文字说明、Do/Don't、生图模板，出图出页面前必读。一个项目可有多份；公司规范放进用户级目录，所有群共用。

    • 内置 16 套 + 备选 9 套
    • 从参考图或网址提色
    • lucide · tabler · phosphor · pixelart

  2. 交付前先核对

    对照风格档查颜色、圆角、字体、图标参数、中文兜底，以及字体在 mac 与 Windows 上是否真的显示——结果贴进交付说明。再按三档宽度真渲染，量重叠、裁切、点击目标、对比度、字号。

    • 风格核对
    • 渲染几何体检
    • 字体可得性

  3. 生图不用 key

    生图借机器上的 Codex 订阅：零 API key，不占群锁，画的时候群里有一条自己更新的进度。原图上改、遮罩局部重绘、透明底，项目风格档自动带上。

    • 原图上改
    • 局部重绘
    • 透明底

  4. 原型直接在群里看

    做好的原型起成局域网服务，端口按群固定；跨轮存活，闲置 30 分钟自动停，控制台里可见可停。

    • 局域网预览
    • 按群固定端口
    • 闲置自动停

画板闭环

飞书 限定

第一次要展示图时，守护进程自动建画板并挂成群标签页。画箭头、贴便签、写评论，点「按标注改图」，结果回填同一张卡。历史版本与标注全部保留，画板就是这份设计的演变档案。画板只放设计方案：要翻找的做成可搜索的网页发群，要挑一个的出带序号的对照图。

05 · 场景

六个群，六种活。

同一个守护进程，绑不同的项目：群里说一句，看着它干，拿走结果。

  1. #bugs

    报错贴进群，回来的是 PR。

    研发群里贴了一段 500 堆栈。

    SintBot 读堆栈、在项目目录里定位原因、改掉、开 PR，把 diff 贴回线程。

    为什么赢：报错、修复、PR 在同一条线程里，终端前不用有人。

  2. #design

    一句话，要一版首页。

    设计群里有人要落地页的第一版。

    它读项目风格档——没有就先给三个候选，比如科技深色、精密仪表、瑞士网格——出图做页面，核对结果随交付一起贴出来。

    为什么赢：规范在仓库里，机器人还要证明自己照办了。

  3. #standup

    每天 09:30，日报自己来。

    有人在群里一句话排了个定时任务。

    到 09:30，任务像收到一条消息那样触发：SintBot 汇总 24 小时的提交，发到群里。

    为什么赢：人到不到，日报都在。

  4. #ship-room

    项目做到一半，换个大脑。

    有人在群里敲了 /model 加一个名字。

    同一个项目、同一批记忆文件，下一轮从 Claude 换成 GLM 接着干。成本自己定，按群定。

    为什么赢：一套 agent，多个大脑，不用重新配。

  5. #deploys

    这个群只能看，那个群才能改。

    两个群绑了同一个项目。

    只读群能看不能动；完全访问群才能改代码、部署。敏感值出群前先打码。

    为什么赢：权限挂在群上，不靠人记。

  6. #review

    原型不出群就能评。

    页面做完了，团队想点开看看。

    SintBot 起成局域网预览，链接发群；/issue 一句话提反馈，上一轮的技术指纹自动附上。

    为什么赢：反馈带着上下文来，不是一张截图。

06 · 治理

默认只读，你说了才能动。

三层权限，全部按群设、没有全局开关——没配置过的群，只能读。

  1. ①

    执行模式

    只读，或完全访问。没设就是只读。

  2. ②

    工具白名单 / 黑名单

    三档预设：只读、开发、全信任；也可以自己列。

  3. ③

    目录围栏

    agent 只能在这个群绑定的项目目录里干活；能绑的目录也只限你的项目根目录之内，符号链接绕不出去。

  1. 01

    出站先脱敏

    消息到群之前先过 13 类模式：Bearer、JWT、API key 前缀、AWS、GitHub、PEM、键值对、邮箱、手机号。密钥永远遮，PII 按群开关。

    • 13 类模式
    • 密钥永远遮
    • PII 按群
  2. 02

    群里八条命令

    /status 报已跑时长、步数、最近动静、排队、会话；/hud 报额度。Claude 5 小时窗用过 90%、Codex 7 天窗用过 95%，群里会提醒。

    • /help
    • /model
    • /new
    • /stop
    • /skip
    • /status
    • /issue
    • /hud
  3. 03

    该安静时安静

    群一暂停就什么都不跑，定时任务也停。闲聊不回；消息撤回，那一轮就停。/issue 提反馈，自动附上一轮的技术指纹。

    • 群可暂停
    • 撤回即停
    • 反馈本

接管浏览器

飞书 限定

它用浏览器干活时撞上登录、验证码、滑块或扫码，会往群里发一张卡：卡住那一页的截图、为什么要你、一个按钮。点开就在手机或电脑上亲手操作那一页——点、拖、输入、两指缩放；登录态留在它那边，它接着干。链接只能打开一次、默认 10 分钟内有效、只通向那一页，卡片会翻成「接管中」「已结束」「已过期」。密码和验证码不用再往群里发。

07 · 控制台

一个本地网页，管所有群。

守护进程自己提供控制台——零依赖的单页网页，默认只在本机；要开出去，局域网靠密码，挂到你自己的 HTTPS 域名上则只放行名单里的管理员用飞书登录。

08 · 长跑可靠

为连跑几周而写。

没人盯着的守护进程得自己照顾自己：轮次不挂死，队列不堆积，重启不丢活。

  1. 01

    永不挂死

    每轮 30 分钟上限，全局同时两轮；25 秒没输出先回「已收到」，卡住 20 秒硬释放；40 万 token 自动压缩，看门狗自动重连。

    • 30 分钟上限
    • 看门狗
    • 自动压缩
  2. 02

    每群一条队列，出队合并

    每群一把锁、一条队列；跑着时来的消息，出队时合并成一轮。/stop 全停含排队，/skip 只跳当前。

    • 每群一把锁
    • 出队合并
  3. 03

    重启补做，不丢活

    被发版或重启打断的那一轮，两小时内自动重做。常驻：macOS 用 launchd 并防休眠，Windows 用 NSSM 或任务计划。

    • 2 小时内补做
    • launchd
    • NSSM
  4. 04

    一句话排定时任务

    cron、daily 别名，或直接写「每天 09:00」。到点可以像收到消息一样叫醒 agent，也可以只发提醒，或只跑一次。

    • cron
    • 中文简写
    • 一次性
  5. 05

    有事说人话

    升级后把新能力发到各个群。模型那边排不上队时说句人话，已经写出来的保住，过一会儿发一句「继续」就接着做；长会话自动压缩会告诉群，查得到额度就一并报上。

    • 升级播报
    • 出错说人话
    • 压缩提示
  6. 06

    依赖少，出网会分流

    Node 18.17 起，运行时依赖两个；Claude Code 和 Codex 你自己装。官方 Claude 走代理，国内端点直连，自动分流。

    • Node ≥ 18.17
    • 2 个运行时依赖
    • 代理自动分流

09 · 免费插件

cc-bot——免费的另一种跑法。

cc-bot 是 MIT 的 Claude Code 插件：活在你的交互会话里，跟随该会话的模型，自带 Slack 与飞书适配器——没有守护进程、没有控制台。

Claude Code 插件 · v0.1.48 MIT Slack · 飞书 github.com/WaterTian/cc-bot

四步开启群聊驱动的仓库。

/cc-bot:setup 在 Claude Code 内完整跑完——幂等、识别版本、能自动识别的都自动识别。

  1. 01

    安装 cc-bot 插件

    # inside Claude Code
/plugin marketplace add WaterTian/cc-bot
/plugin install cc-bot@cc-bot

    然后在任意项目里执行 /cc-bot:setup。问到 IM 时选 Slack。

  2. 02

    用 manifest 创建 Slack 应用

    打开 api.slack.com/apps → Create New App → From a manifest，粘贴下面的 YAML。

    展开 manifestYAML 
    # templates/slack-manifest.yaml — bot scopes & Socket Mode
display_information:
  name: cc-bot
  description: Claude Code-powered group project assistant
  background_color: "#1f3a2a"

features:
  bot_user:
    display_name: cc-bot
    always_online: true

oauth_config:
  scopes:
    bot:
      - app_mentions:read   # listen for @cc-bot
      - channels:history    # read public channels
      - channels:read
      - chat:write          # post messages
      - files:read          # download images
      - files:write
      - groups:history      # private channels
      - groups:read
      - users:read

settings:
  event_subscriptions:
    bot_events:
      - message.channels
      - message.groups
      - app_mention
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true  # no public webhook needed
  token_rotation_enabled: false

  3. 03

    生成两个 Token

    在新建应用的 Basic Information 页面：

    • App-Level Token——命名为 cc-bot-socket，scope 选 connections:write，复制 xapp-1-…。
    • Install to Workspace → Allow，复制 Bot User OAuth Token（xoxb-…）。

    /cc-bot:setup 提示时把两个 token 粘进去。cc-bot 通过 auth.test 校验，写入 .cc-bot/profiles/active.json。

  4. 04

    把 cc-bot 拉进频道

    把 channel ID 粘进去，在 Slack 里执行 /invite @cc-bot，bot 会发一条探测消息。然后上线：

    /cc-bot:start

    频道会收到一条上线消息。接下来，把它当队友一样说话即可。

斜杠命令

  • /cc-bot:setup — Slack / 飞书 引导式接入
  • /cc-bot:start — 上线
  • /cc-bot:stop — 下线
  • /cc-bot:new-profile <name> — 克隆 profile 模板
  • /cc-bot:switch <name> — 切换当前 profile
  • /cc-bot:doctor — 健康检查与诊断

一个跑在你自己机器上的守护进程：把一个聊天群（飞书或 Slack）绑定到一个项目。群里谁都能派活，它在这个项目里运行 Claude Code 或 Codex，把进度和结果发回群里。
它和 cc-bot 有什么区别？
cc-bot 是免费、MIT 许可的 Claude Code 插件，运行在你的交互会话里，用的就是该会话的模型。SintBot 是独立的守护进程：不需要有人守着终端，每个群有自己的项目、模型和权限，同时驱动 Claude Code 和 Codex，并自带本地控制台。
支持哪些模型？
Claude 用本机的 Claude Code 登录，GPT 用你的 Codex 订阅登录；GLM、DeepSeek、MiniMax、Kimi 用你自己的 key；也可以接任何兼容 Anthropic 接口的端点，包括你自己部署的开源模型。每个群各选各的，群里任何人都能用 /model 切换。
换模型会丢掉项目记忆吗？
不会。换模型会开一段新对话，但项目里的 CLAUDE.md、AGENTS.md 和记忆目录会交给接下来运行的 agent，约定和长期记忆都还在。长会话会自动压缩。
代码和数据存在哪？
都在你自己的机器上：项目目录、会话、记忆和日志都留在本地。守护进程只和你配置的服务通信（聊天平台和模型端点），不会发给我们。消息发进群之前，密钥类内容会先被遮掉。
需要服务器或公网 IP 吗？
不需要。它跑在一台常开的 Mac 或 Windows 电脑上，只向外连接：飞书用 WebSocket 长连接，Slack 用 Socket Mode。控制台默认只在本机，除非你自己选择开放。
默认情况下 agent 能做什么？
只能读。权限按群设置，没有全局开关：没配置过的群只能读取。你可以给某个群完全访问或某档工具预设，agent 始终只能在这个群绑定的项目目录里工作。
怎么获取 SintBot？
它不是公开下载。订阅 Pro 是支持项目开发；付款后用下单邮箱写信到 support@sintbot.com，即可获取当前版本的安装包。按现状提供，以可读源码形式交付，适用源码可见的许可。想先免费试？cc-bot 两条命令就能装进 Claude Code。
