安装指南 1.3.0

从你的 Mac连到项目群

完成安装、飞书连接和项目配置，用第一条真实消息验证整个流程。

macOSNode.js 22+Codex飞书
开始安装 ↓

01

准备项目所在的 Mac

本指南对应 SintBot 1.3.0，使用 macOS、Node.js 22 及以上、Codex 和一个中国区飞书项目群，以前台方式运行。

  • 项目已经保存在这台 Mac 上，知道它的绝对路径。
  • Node.js 版本为 22 或以上。
  • Codex 已安装、已登录，并能在本地终端实际使用。
  • 可以创建飞书企业自建应用，并把机器人加入测试群。
Terminal
node --version
codex --version

先确认两条命令都能输出版本，再继续。已有的 Codex 安装和账号数据可以直接使用。

版本检查失败怎么办？

如果提示找不到命令，先完成对应工具的安装，并重新打开终端。Node.js 可从 官方站点获取；Codex 按其官方说明完成安装与登录。SintBot 安装器负责安装 SintBot 本身。

02

下载、检查，再安装

在本地终端下载安装器，先预览它要做的操作，再运行同一份文件。

Terminal
curl -fsSL https://sintbot.com/install.sh -o /tmp/sintbot-install.sh
bash /tmp/sintbot-install.sh --dry-run
bash /tmp/sintbot-install.sh

--dry-run 只展示安装计划，不下载程序包，也不修改文件。安装器把精确的 sintbot@1.3.0 放到独立发行目录，并检查入口、内置核心和飞书模块。

安装后，使用这个明确的入口确认版本：

Terminal
SINTBOT="$HOME/.local/share/sintbot/releases/1.3.0/bin/sintbot"
"$SINTBOT" --version
"$SINTBOT" help
你应该看到

版本输出为 1.3.0，帮助内容能正常显示。安装完成后，机器人还没有连接飞书。

安装位置与已有文件

默认目录是 ~/.local/share/sintbot/releases/1.3.0。安装器保留全局程序包、终端配置、应用配置和服务；如果目标目录已经存在，它会停止，避免覆盖。

需要其他位置时，用 --prefix /全新/绝对/目录 指定新目录，并把后续 SINTBOT 变量改成该目录下的 bin/sintbot。

03

准备飞书应用和项目群

在 飞书开放平台创建企业自建应用，按顺序完成下面的设置。

  1. 启用机器人。在应用中添加机器人能力。
  2. 设置消息权限。授予接收消息和以机器人身份回复消息所需的权限。
  3. 选择长连接。在事件订阅中选择长连接接收事件，并订阅消息接收事件。
  4. 发布并入群。发布应用，把机器人加入一个专用测试群，取得该群的 oc_… 群 ID。
把凭据留在本机

在将要启动 SintBot 的终端中，把应用 ID 和应用密钥分别设置为 FEISHU_APP_ID、FEISHU_APP_SECRET 环境变量。不要把应用密钥发到群里或提交到项目仓库。

每次新开终端，都要确保这两个环境变量已配置。后面的配置文件只保存变量名称，不保存密钥。

在当前终端输入应用凭据

在飞书开放平台打开自己的应用，从「凭证与基础信息」页取得 App ID 和 App Secret。在 macOS 默认的 zsh 终端中，逐行执行以下命令；出现提示后粘贴对应值并回车。密钥输入时不回显，也不会作为命令写入历史。

zsh
read -r "FEISHU_APP_ID?Feishu App ID: "
read -rs "FEISHU_APP_SECRET?Feishu App Secret: "
printf '\n'
export FEISHU_APP_ID FEISHU_APP_SECRET
[[ -n "$FEISHU_APP_ID" && -n "$FEISHU_APP_SECRET" ]] && printf 'Credentials set\n'

看到 Credentials set 表示两个值已设置，不会显示密钥。继续在这个终端完成后续步骤；新开终端时重新设置凭据。

04

把这个群绑定到项目

先创建私有配置目录：

Terminal
mkdir -p ~/.sbot && chmod 700 ~/.sbot

在文本编辑器中新建 ~/.sbot/config-1.3.0.json，填入下面的配置。把群 ID 和项目路径替换为自己的真实值，项目目录必须已经存在。

config-1.3.0.json
{
  "defaultProvider": "codex",
  "providers": { "codex": { "runner": "codex" } },
  "feishu": {
    "appId": "env:FEISHU_APP_ID",
    "appSecret": "env:FEISHU_APP_SECRET",
    "onlyWhenMentioned": false
  },
  "groups": {
    "oc_REPLACE_WITH_YOUR_CHAT_ID": {
      "platform": "feishu",
      "provider": "codex",
      "workdir": "/absolute/path/to/your/project",
      "permissionMode": "dontAsk",
      "codexSteer": false,
      "codexApp": false
    }
  }
}

保存后限制配置文件的访问权限：

Terminal
chmod 600 ~/.sbot/config-1.3.0.json
这份配置怎样工作？
workdir
群所绑定的项目目录。使用绝对路径。
permissionMode: "dontAsk"
这个示例以只读权限开始，适合先验证消息和项目读取。
onlyWhenMentioned: false
接收该群里的普通消息，因此请先使用专用测试群。
codexSteer / codexApp
本指南保留这两个显式的 false 设置。
如何只响应 @ 机器人的消息？

将 onlyWhenMentioned 设为 true，并在 feishu 对象中补上该应用实际的 botOpenId。它是机器人的 Open ID，不是应用 ID 或群 ID；缺少它时，启动检查会拒绝该配置。

05

先初始化，再检查启动

在同一个终端中按顺序执行。初始化只用于全新安装，运行一次即可。

建立持久日志

Terminal
"$SINTBOT" init --config "$HOME/.sbot/config-1.3.0.json"

init 创建 ~/.sbot/c2-v2.log，用于记录消息任务的处理状态。

检查本地配置

Terminal
"$SINTBOT" start --config "$HOME/.sbot/config-1.3.0.json" --preflight

预检核对本地配置和组件装配；它不会连接飞书，真实消息需要在下一步验证。

连接项目群

Terminal
"$SINTBOT" start --config "$HOME/.sbot/config-1.3.0.json"

保持这个终端开启。SintBot 在这里运行，并连接配置中的飞书项目群。

已有状态受到保护

如果初始化提示已有日志、旧状态或未结收据，保留它们并核对来源，不要删除文件绕过检查。一个飞书应用同一时间只连接一个 SintBot 进程。

06

用真实消息验证连接

在刚才的飞书群里发送：

请读取当前项目 README.md 的第一行，只回复这一行。

把回复与项目文件对照。这样可以同时核对群连接、Codex 执行和项目路径。

停止与重新启动

回到运行终端，按 Ctrl + C 并等待进程退出。重新确认飞书环境变量后，运行同一条启动命令：

Terminal
SINTBOT="$HOME/.local/share/sintbot/releases/1.3.0/bin/sintbot"
"$SINTBOT" start --config "$HOME/.sbot/config-1.3.0.json"

日常重启使用 start，不用重新执行 init。

机器人没有回复

先查看运行终端的报错，再核对应用是否已发布、机器人是否在目标群、消息权限与事件订阅是否齐全、环境变量是否存在、群 ID 与项目路径是否准确。预检成功并不等于飞书认证和消息送达成功。

任务失败或提示未结收据

保留日志与状态，先核对任务实际执行到哪一步。不要清空日志、覆盖未知结果或连续重发相同任务。

准备切换版本时

先等待当前任务完成并停止进程，保留配置与状态备份，再确认新旧版本的状态兼容性。仅保留旧程序包，不等于可以安全回退任务状态。
