安装指南 1.4.12

从你的 Mac连到项目群

完成安装、飞书连接和项目配置，用第一条真实消息验证整个流程。

macOSNode.js 22+Codex / Claude Code飞书
开始安装 ↓

01

准备项目所在的 Mac

本指南对应 SintBot 1.4.12，使用 macOS、Node.js 22 及以上、Codex 或 Claude Code，以及 1–32 个中国区飞书项目群，以前台方式运行。

  • 项目已经保存在这台 Mac 上，知道它的绝对路径。
  • Node.js 版本为 22 或以上。
  • Codex 或 Claude Code 至少一个已安装、已登录，并能在本地终端实际使用。
  • 可以创建飞书企业自建应用，并把机器人加入测试群。
如何检查环境？
Terminal
node --version
codex --version
claude --version

先确认 Node.js 和你要用的执行器都能输出版本，再继续。已有的 Codex 或 Claude Code 安装和账号数据可以直接使用。

版本检查失败怎么办？

如果提示找不到命令，先完成对应工具的安装，并重新打开终端。Node.js 可从 官方站点获取；Codex 按其官方说明完成安装与登录。SintBot 安装器负责安装 SintBot 本身。

02

一行安装 SintBot

复制到本地终端执行。环境检查、程序安装和结果验证由安装器自动完成。

Terminal
curl -fsSL https://sintbot.com/install.sh | bash
安装完成

看到 Installed and verified SintBot 1.4.12 即表示安装完成。接下来配置飞书和项目。

可选：先预览安装计划

如需在安装前查看将执行的操作，改用下面这条命令；不下载程序包、不改配置。确认后执行上方安装命令。

Terminal
curl -fsSL https://sintbot.com/install.sh | bash -s -- --dry-run
可选：手动检查版本与帮助
Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" --version
"$SINTBOT" help

程序安装到 ~/.local/share/sintbot。完成后按下方步骤连接飞书和项目。

03

准备飞书应用和项目群

在 飞书开放平台创建企业自建应用，按顺序完成下面的设置。

  1. 启用机器人。在应用中添加机器人能力。
  2. 设置消息权限。授予接收消息和以机器人身份回复消息所需的权限。
  3. 选择长连接。在事件订阅中选择长连接接收事件，并订阅消息接收事件。
  4. 发布并入群。发布应用，把机器人加入一个专用测试群，取得该群的 oc_… 群 ID。
把凭据留在本机

在将要启动 SintBot 的终端中，把应用 ID 和应用密钥分别设置为 FEISHU_APP_ID、FEISHU_APP_SECRET 环境变量。不要把应用密钥发到群里或提交到项目仓库。

每次新开终端，都要确保这两个环境变量已配置。后面的配置文件只保存变量名称，不保存密钥。

在当前终端输入应用凭据

在飞书开放平台打开自己的应用，从「凭证与基础信息」页取得 App ID 和 App Secret。在 macOS 默认的 zsh 终端中，逐行执行以下命令；出现提示后粘贴对应值并回车。密钥输入时不回显，也不会作为命令写入历史。

zsh
read -r "FEISHU_APP_ID?Feishu App ID: "
read -rs "FEISHU_APP_SECRET?Feishu App Secret: "
printf '\n'
export FEISHU_APP_ID FEISHU_APP_SECRET
[[ -n "$FEISHU_APP_ID" && -n "$FEISHU_APP_SECRET" ]] && printf 'Credentials set\n'

看到 Credentials set 表示两个值已设置，不会显示密钥。继续在这个终端完成后续步骤；新开终端时重新设置凭据。

04

把这个群绑定到项目

先创建私有配置目录：

Terminal
mkdir -p ~/.sbot && chmod 700 ~/.sbot

在文本编辑器中新建 ~/.sbot/config.json，填入下面的配置。把群 ID 和项目路径替换为自己的真实值，项目目录必须已经存在。

config.json
{
  "defaultProvider": "codex",
  "providers": {
    "codex": { "runner": "codex" },
    "claude": { "runner": "claude" }
  },
  "feishu": {
    "appId": "env:FEISHU_APP_ID",
    "appSecret": "env:FEISHU_APP_SECRET",
    "onlyWhenMentioned": false
  },
  "groups": {
    "oc_REPLACE_WITH_FIRST_CHAT_ID": {
      "platform": "feishu",
      "provider": "codex",
      "workdir": "/absolute/path/to/first/project",
      "permissionMode": "dontAsk",
      "steer": true
    },
    "oc_REPLACE_WITH_SECOND_CHAT_ID": {
      "platform": "feishu",
      "provider": "claude",
      "workdir": "/absolute/path/to/second/project",
      "permissionMode": "dontAsk"
    }
  }
}

保存后限制配置文件的访问权限：

Terminal
chmod 600 ~/.sbot/config.json
这份配置怎样工作？
workdir
群所绑定的项目目录。使用绝对路径。
permissionMode: "dontAsk"
这个示例以受限权限开始，适合先验证消息和项目读取。需要它修改文件、执行命令时改为 "bypassPermissions"（完全访问）。
onlyWhenMentioned: false
接收该群里的普通消息，因此请先使用专用测试群。
provider
每个群选 codex 或 claude。只有一个群时删掉另一项。要固定 Claude 型号，在 providers.claude 里加 "model"。
steer: true
Codex 和 Claude Code 默认开启忙时跟进；设为 steer: false 则排队。Claude Code 须具备所需输入能力，长工具调用可能延迟读取。
如何只响应 @ 机器人的消息？

将 onlyWhenMentioned 设为 true，并在 feishu 对象中补上该应用实际的 botOpenId。它是机器人的 Open ID，不是应用 ID 或群 ID；缺少它时，启动检查会拒绝该配置。

05

首次启动，复制这一组

在刚才输入飞书凭据的终端中，整组复制执行。仅全新安装执行一次；之后重启使用下一节的启动命令。

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" init --config "$HOME/.sbot/config.json" &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --preflight &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui

它依次初始化消息日志、预检配置和执行器、连接飞书并打开本机控制台；任何一步失败，后续步骤就不会执行。保持终端开启，再到群里验证消息。

初始化只运行一次

如果提示日志已经存在，先核对是否已完成初始化；正常重启只运行启动命令。不要删除任务日志。一个飞书应用同一时间只连接一个 SintBot 进程。

06

用真实消息验证连接

在刚才的飞书群里发送：

请读取当前项目 README.md 的第一行，只回复这一行。

把回复与项目文件对照。这样可以同时核对群连接、执行器和项目路径。

群里的命令与控制台

直接发文字就是派任务；模型开始输出时回复卡片就会出现，25 秒还没有输出也会先出现。运行中卡片显示已跑多久、正在做什么和已完成的步骤，结束后这些步骤收进「过程」折叠区。下面的命令立即应答，不占用任务：

/status
模型、项目、是否在忙（在忙时含步数和正在做什么）和排队数。
/skip
只放弃当前任务，排队的接着处理，之前的对话保留。
/stop
停止当前任务，连同排队的一起取消；之前的对话保留。
/new
在本群空闲时忘掉之前的对话，开始新的一段。
/model
查看可选模型；/model 名字 在本群空闲时切换，并开始新的一段对话。
/hud
当前模型的额度与本段对话的用量。
/issue 一句话
记下问题反馈，在控制台查看。
/help
查看可用命令，以及本群的项目和模型。

命令单独发一条；除 /issue 和 /model 外，后面不要跟别的字。飞书应用订阅了消息撤回事件时，撤回自己发的消息即取消那件事。已交给执行器的补话被撤回时取消整轮，包括已受理但尚未读取的补话。

带 --ui 启动后，在本机打开 http://127.0.0.1:4600，可以查看各群、停止任务、给空闲的群开新会话、绑定新群、给空闲的群切换模型或项目目录，以及添加和设置模型。开启局域网访问前，先在控制台设置里设访问密码。不用控制台也能加群：在配置里加上新群后重启，会自动登记。

停止与重新启动

回到运行终端，按 Ctrl + C 并等待进程退出。重新确认飞书环境变量后，运行同一条启动命令：

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui

日常重启使用 start，不用重新执行 init。

机器人没有回复

先查看运行终端的报错，再核对应用是否已发布、机器人是否在目标群、消息权限与事件订阅是否齐全、环境变量是否存在、群 ID 与项目路径是否准确。预检成功并不等于飞书认证和消息送达成功。

群被暂停或提示未结收据

某个群上一轮的结果无法确认时，只暂停这个群，其他群照常。先重启服务；仍然暂停的，核对任务实际执行到哪一步，再停止服务，运行 sintbot incident seal --group 群ID 后重新启动。不要清空日志、覆盖未知结果或连续重发相同任务。
