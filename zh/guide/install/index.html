安装指南 1.4.17

从你的 Mac连到项目群

完成安装、飞书连接和项目配置，用第一条真实消息验证整个流程。

macOSNode.js 22+Codex / Claude Code飞书
开始安装 ↓

01

准备项目所在的 Mac

本指南对应 SintBot 1.4.17，使用 macOS、Node.js 22 及以上、Codex 或 Claude Code，以及 1–32 个中国区飞书项目群，以前台方式运行。

  • 可以先用自动创建的项目目录，也可以选择这台 Mac 上已有的项目。
  • Node.js 版本为 22 或以上。
  • Codex 或 Claude Code 至少一个已安装、已登录，并能在本地终端实际使用。
  • 手机已登录飞书，可以使用企业或团队身份扫码确认。
如何检查环境？
Terminal
node --version
codex --version
claude --version

先确认 Node.js 和你要用的执行器都能输出版本，再继续。已有的 Codex 或 Claude Code 安装和账号数据可以直接使用。

版本检查失败怎么办？

如果提示找不到命令，先完成对应工具的安装，并重新打开终端。Node.js 可从 官方站点获取；所选编码助手按其官方说明完成安装与登录。SintBot 安装器负责安装 SintBot 本身。

02

一行安装 SintBot

复制到本地终端执行。环境检查、程序安装和结果验证由安装器自动完成。

Terminal
curl -fsSL https://sintbot.com/install.sh | bash
安装完成

看到 Installed and verified SintBot 1.4.17 即表示安装完成。接下来配置飞书和项目。

可选：先预览安装计划

如需在安装前查看将执行的操作，改用下面这条命令；不下载程序包、不改配置。确认后执行上方安装命令。

Terminal
curl -fsSL https://sintbot.com/install.sh | bash -s -- --dry-run
可选：手动检查版本与帮助
Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" --version
"$SINTBOT" help

程序安装到 ~/.local/share/sintbot。完成后按下方步骤连接飞书和项目。

03

手机扫码接入飞书

在 Mac 上运行接入命令，用手机飞书扫一扫并确认。请选择企业或团队身份；没有组织时先在飞书创建团队。

Terminal
"$HOME/.local/share/sintbot/bin/sintbot" connect
  1. 手机扫码确认。二维码在本机页面打开，手机确认机器人应用所属的团队。
  2. 自动创建应用和群。接入流程取得凭据、检查配置、创建项目目录和群，把你加入群并保存配置。
  3. 按提示启动。完成后到新群发任务，无需手写配置或复制应用密钥。
需要管理员批准，或扫码没有完成？

权限与发布审核取决于组织设置。按页面提示联系管理员；接入中断时按终端给出的续做方式处理，已有应用可以复用。非管理员基础接入、手动接入与失败续做见完整安装指南。

配置保存在哪里？

应用凭据保存在这台 Mac 的 ~/.sbot/config.json，文件权限为 0600。不要把配置或密钥发到群里、提交到仓库。已有绑定群的配置不会被扫码流程替换。

04

项目目录已准备好

默认会创建 ~/Projects/sintbot 和一份 README，并绑定到刚建立的群。先用默认设置完成第一条任务，之后在控制台「群 · 项目」管理项目目录和模型。

想接入已有项目？

扫码前在接入命令后加 --workdir /项目的绝对路径；目录必须已存在。新项目可用 --name 项目名 指定目录名。不要把整个家目录作为项目目录。

05

启动 SintBot

扫码接入已经完成初始化。复制终端显示的启动命令，或在默认安装下运行：

Terminal
"$HOME/.local/share/sintbot/bin/sintbot" start --config "$HOME/.sbot/config.json" --ui

保持终端开启。控制台「设置 → 飞书」显示连接状态，「群 · 项目」管理绑定群；公网地址和管理员登录是按需设置，不影响群里的基本使用。

已有安装直接启动

日常重启不需要重新扫码或初始化。自定义过数据目录时，请沿用接入流程显示的完整启动命令。

06

用真实消息验证连接

在刚才的飞书群里发送：

请读取当前项目 README.md 的第一行，只回复这一行。

把回复与项目文件对照。这样可以同时核对群连接、执行器和项目路径。

群里的命令与控制台

直接发文字就是派任务；模型开始输出时回复卡片就会出现，25 秒还没有输出也会先出现。运行中卡片显示已跑多久、正在做什么和已完成的步骤，结束后这些步骤收进「过程」折叠区。下面的命令立即应答，不占用任务：

/status
模型、项目、是否在忙（在忙时含步数和正在做什么）和排队数。
/skip
只放弃当前任务，排队的接着处理，之前的对话保留。
/stop
停止当前任务，连同排队的一起取消；之前的对话保留。
/new
在本群空闲时忘掉之前的对话，开始新的一段。
/model
打开点选卡，选后端、型号和思考深度后点「确认更新」；也可直接发 /model high、/model 型号、/model 后端。换型号或调深度接着当前对话，换后端开始新的一段对话；只在本群空闲时生效。
/hud
当前模型的额度与本段对话的用量。
/issue 一句话
记下问题反馈，在控制台查看。
/help
查看可用命令，以及本群的项目和模型。

命令单独发一条；除 /issue 和 /model 外，后面不要跟别的字。飞书应用订阅了消息撤回事件时，撤回自己发的消息即取消那件事。已交给执行器的补话被撤回时取消整轮，包括已受理但尚未读取的补话。

带 --ui 启动后，在本机打开 http://127.0.0.1:4600，可以查看各群、停止任务、给空闲的群开新会话、绑定新群、给空闲的群切换模型或项目目录，以及添加和设置模型。开启局域网访问前，先在控制台设置里设访问密码。不用控制台也能加群：在配置里加上新群后重启，会自动登记。

型号与思考深度按群选：在「群 · 项目」卡的「模型」行选后端和型号，下一行选深度，清单取自本机 Codex / Claude Code 的实时数据；订阅登录的模型卡上不再设型号和深度，第三方端点的型号仍在模型卡上设置。升级后，模型卡上原有的型号和深度会自动写进各群，生效值不变、会话不重置。

模型设置分为型号与推理、上下文与压缩、连接与登录。Codex 窗口可选执行器默认或自定义，保存时校验已知上限；压缩也只保留默认与自定义，按需显示数值。Codex 使用阈值，Claude Code 使用压缩窗口，实际都可能提前触发。旧显式全局值转为原有模型的独立设置，新模型使用执行器默认。设置从下轮生效并保留会话；容量详情区分设置值与实际回报。

停止与重新启动

回到运行终端，按 Ctrl + C 并等待进程退出。沿用接入时的配置，运行同一条启动命令：

Terminal
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui

日常重启使用 start，不用重新执行 init。

机器人没有回复

先查看运行终端的报错，再核对应用是否已发布、机器人是否在目标群、消息权限与事件订阅是否齐全、配置凭据是否有效、项目群是否已绑定。预检成功并不等于飞书认证和消息送达成功。

群被暂停或提示未结收据

某个群上一轮的结果无法确认时，只暂停这个群，其他群照常。先重启服务；仍然暂停的，核对任务实际执行到哪一步，再停止服务，运行 sintbot incident seal --group 群ID 后重新启动。不要清空日志、覆盖未知结果或连续重发相同任务。
