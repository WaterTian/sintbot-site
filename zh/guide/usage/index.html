使用说明

把项目工作放进群聊

在群里说明任务，跟进进度，核对交付。项目文件和保存下来的笔记，让下一轮工作接得上。

从第一条消息开始 ↓

首次使用先按安装指南扫码接入，应用和项目群会自动创建。控制台「设置 → 飞书」查看连接状态，「群 · 项目」管理项目；已有应用无需重新扫码。

01

从一个小任务开始

在已经绑定项目的群里，先发一条只读请求，选择一个能直接对照本地文件核验的问题。

第一条消息
读取这个项目 README 的第一行，只回复这一行。不要修改任何文件。
  1. 在项目群发送

    把请求发到已配置的项目群。如果接入时设置了需要提及机器人，就先 @ 它。

  2. 查看返回内容

    SintBot 在这个群绑定的项目目录里工作，把进度和最终回复发回群里。

  3. 与文件核对

    检查回复是否和 README 一致，确认群消息、编码助手和回复这条路径完整可用。

第一次使用前，先完成安装和接入步骤。安装成功与模型能够处理群消息，需要分别确认。

02

把任务说到可以验收

说明目标、上下文、需要保留的部分，以及做完后如何核对。截图或文件比文字更清楚时，直接附在群里。

一条开发任务示例
优化首页在手机上的导航。
沿用现有字体、颜色和桌面布局。
参考附件截图定位问题。
检查 390 px 和 768 px 两种宽度，完成后发截图并说明改动。
希望先查清原因

明确要求先给原因、涉及的文件和修复方案。例如：“登录按钮点了没反应，先检查相关代码和日志，说明原因与最小修复范围。”

希望直接修改

说明可以改代码，写清期望行为和验收结果，并指出需要保留的文件或现有功能。

任务里有多个部分

按顺序列出交付项，说明相互依赖。说明哪些部分可以独立处理，以及最后如何统一集成和核对。

03

在原对话里核对交付

进度和最终结果都会回到项目群。根据任务不同，交付可以是说明、代码改动、图片、报告或可交互预览。

  1. 先看结果说明

    核对改了什么、如何检查，以及哪些地方还需要你作决定。

  2. 再看实际产物

    打开文件或预览。代码任务还可以检查项目里的改动，并运行适合这次修改的验证。

  3. 继续给具体反馈

    指明页面区块、文件、截图位置或行为，同时说清要调整什么、哪些地方已经合适。

一次明确的反馈
手机布局已经合适，保留。
用现有强调色，让导航当前选中项更容易辨认。
检查同样的两种宽度后，发更新截图。
1.4.21 任务进行中如何补充要求

直接在项目群发送补充。Claude Code 与 Codex 默认开启忙时跟进，关闭或暂不支持时排队。“已加入”表示模型已读取，执行较长的工具步骤时可能需要等待。

群忙时也可以使用控制台「插话」：按本群跟进设置，等待模型读取或进入队列。「已受理」不代表模型已经读取。新会话和模型切换仍需等群空闲后操作。

04

先选编码助手，再选模型

编码助手负责执行工作，背后的模型服务负责处理模型请求。这是两个不同的配置层次。

编码助手模型或服务配置位置
Claude CodeClaudeClaude Code 账号与配置
Claude CodeGLM、MiniMax、DeepSeek兼容服务地址与自己的服务凭据
Claude CodeKimi 或其他兼容服务自定义兼容服务地址
CodexGPTCodex 账号与模型配置

在项目的模型配置中选择执行器和模型。服务密钥保存在本地配置，不要发进群里。实际可选项取决于这台机器已经配置的编码助手和账号。

切换前，先留下交接

让 SintBot 把决定和未完成事项写进项目。换后端会开启新的对话，同一后端换型号或调深度接着当前对话；保存的文件和共享笔记都会保留。

扫码前，SintBot 读取所选执行器的实时模型清单，把推荐型号和思考深度明确保存为新群的初始设置。接入页会显示这些值，之后可在「群 · 项目」修改。若无法取得实时推荐，流程会在创建新应用前停下；请检查执行器登录和网络后重试。已有群的选择保持不变。

型号与思考深度按群选：在控制台「群 · 项目」卡上改，或在群里发 /model 打开点选卡，选好后点「确认更新」；也可以直接发 /model high 这类文字。都要等本群空闲。

Codex 速度（Fast）。Codex 模型多一个「速度」选项：标准或 Fast，默认标准。三种开法：群里发 /model fast（回到标准发 /model 标准）；/model 弹出的模型卡上多一行「速度」，照旧先选、再确认；控制台群卡上多一个「速度」下拉。只改速度不会重置会话，任务进行中也能改，下一条消息生效。按群、按模型卡分开记：这个群在 GPT 上开了 Fast，不影响它在别的模型上的设置。只有支持 Fast 的型号才能开，否则直接拒绝、什么都不改；换到不支持的型号时自动回到标准并说一句。开的回执会写明代价：模型能力不变，只是请求排进更高优先级，约快 1.5–2 倍（因型号而异），订阅包含的额度按标准的 2.5 倍扣，另购 credits 按 2 倍扣。没开 Fast 时，每一轮都明确要求标准速度。App Server 明确回报回退时，卡片页脚不再显示 Fast；旧执行器或 exec 路线可能不回报实际档位，不能仅凭 Fast 标记证明加速已生效。

DeepSeek。模型库默认带一张 DeepSeek 卡，未填 Key 时也可在群卡中选择；执行前需在「模型 · 库」填入自己的 API Key。型号与思考深度在「群 · 项目」逐群配置，预设型号为 deepseek-flash[1m]。没填 Key 时启动前会拒绝并提示「这张模型卡还没填 API Key」，不会借用其他凭据。

模型设置分为型号与推理、上下文与压缩、连接与登录。Codex 窗口可选执行器默认或自定义，保存时校验已知上限；压缩也只保留默认与自定义，按需显示数值。Codex 使用阈值，Claude Code 使用压缩窗口，实际都可能提前触发。旧显式全局值转为原有模型的独立设置，新模型使用执行器默认。设置从下轮生效并保留会话；容量详情区分设置值与实际回报。

Claude Code 群在执行器自报支持压缩时，可在两轮之间整理当前会话：上下文达到自定义压缩窗口的一半、且有空余并发名额时运行，群里不发消息。新消息到来会先中断整理，再开始任务；窗口设为 0 时仅关闭空闲整理，轮内压缩交给执行器默认行为。/hud 可查看整理线与上次完成时间，Claude 订阅额度优先读取执行器回报的额度事件。

05

把重要决定写进项目

对话承接正在进行的工作，项目笔记保留下一轮任务或另一个模型需要知道的决定。

  • 项目约定：命名、代码规范、设计方向和验证方式。
  • 当前交接：已经完成什么、还剩什么、下一步具体做什么。
  • 相关依据：关键文件、已确认的原因和决定的出处。
让它保存一份交接
把今天的决定、完成情况和剩余任务写进项目交接。
注明继续工作需要看的文件和验证方式。
保持精简，沿用已有项目约定。

已保存的笔记才是共享项目上下文。没有落到文件里的聊天细节，不会自动变成共享记忆。切换模型或开启新会话前，先核对交接内容。

06

用截图、文件与预览协作

把参考素材发到群里，并说明参考的是排版、字体、配色、交互，还是其中某个组件。

制作或优化界面

指明页面和组件，说明要保留的设计，并要求检查桌面与手机效果。先看交付截图，再打开可交互预览核对操作。

生成或修改图片

说明用途与修改要求。原图内容很重要时，把它作为参考附件，并指出主体、构图或配色中需要保留的部分。

用标注图评审

把标注好的截图发到群里，将迭代稿保存在项目中。需要新版时，指向具体图片或评论，让修改要求有明确落点。

浏览器任务需要本人登录

打开群里的接管入口，自己完成登录或验证，再告诉 SintBot 继续。不要在群聊里发送密码或验证码。

07

安排日常项目工作

明确项目范围、谁在派活，以及编码助手可以使用的权限。

项目群

每个群绑定对应项目。控制台概览集中显示并发、群状态、模型思考深度和最近上报的上下文量。选择群后查看任务，展开可读回复、工具与用量；群行图标提供插话、停止和新会话。

操作权限

初次接入从只读请求开始。需要改文件或执行命令时，由项目管理员配置相应权限。

例行工作

把需要定期检查的事项保存在项目清单里；到时间后，在项目群发送任务，再核对返回的报告。

模型服务

项目文件保存在本机；群消息和模型请求会使用配置的外部服务，并遵循对应账号的条款和用量限制。

1.4.21 前台安装的启动与停止

使用已接入的群时，保持启动终端运行。停止时按 Ctrl-C，等待进程退出。日常重启沿用安装指南里的启动命令，不要重复初始化。

升级时，先在控制台「设置 → 软件更新」查看有没有新版本，再按 Ctrl-C 停止、重新运行一行安装命令、用原来的命令启动。如果用你自己的 launchd 后台任务运行，控制台的「现在升级」会等所有群空闲后安装新版本并切换，新版本连不上时自动换回旧版。

如果某个群被暂停或启动提示未结收据，保留状态，先查清之前的任务是否执行，再按安装指南重启或封存这个群。不要删除日志，也不要盲目重复同一个任务。
